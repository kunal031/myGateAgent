# Dependencies for the deployed functions.
#
# Separate from requirements.txt because that file also carries the
# ingestion toolchain -- gdown, python-docx, python-pptx -- which only
# the local CLIs use. Embedding a book takes hours against Lambda's
# 15-minute ceiling, so ingestion never runs there and shipping its
# dependencies would spend a third of the 250 MB unzipped limit on code
# that cannot execute.
#
# pymupdf stays. It is imported lazily inside import_paper_pdf, so a
# naive import scan reports it unused -- it is not. The worker needs it
# to read an uploaded question paper.
#
# boto3 is provided by the Lambda runtime and deliberately omitted here;
# it stays pinned in requirements.txt for local runs.
#
# This file is the API's dependencies. The worker additionally needs the
# document toolchain (requirements-lambda-worker.txt), which is 92 MB of
# pymupdf, lxml and Pillow that no API route touches. Shipping one set to
# both put the package at 230 MB against a 250 MB limit -- close enough
# that a single dependency update would have broken the deploy.
